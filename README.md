# AI工作台

一个面向个人创作者的本地优先工作台，用于统一管理日常计划、内容创作、学习、健身和阶段复盘。项目采用单页 HTML 实现，不依赖前端构建工具；数据可以保存在浏览器本地，也可以写入项目下的 `data/` 文件夹，并通过 iCloud 在多台设备之间同步。

## 功能概览

- **工作台首页**：汇总任务完成情况、每日打卡、连续记录、近况趋势和待办事项。
- **每日计划**：按早晨、下午、晚间组织任务，支持新增、完成、编辑、删除、撤销和将未完成任务结转到明天。
- **健身打卡**：自定义本周训练计划，支持跑步、爬楼梯、游泳、力量训练等类型；完成训练时可记录时长、卡路里和备注，并查看训练历史、连续训练天数和热力图。
- **选题灵感**：维护内容选题、灵感描述和待发展的方向。
- **内容复盘**：记录内容表现和复盘结论，部分指标支持手动维护。
- **AI 学习、英语学习、科研、AI 漫剧**：通过任务、学习记录或阶段内容管理持续推进专项目标。
- **新闻热点**：集中查看预置的科技、创作和热点信息条目。
- **数据管理**：连接数据文件夹、导入/导出 JSON、查看回收站、恢复删除内容、清空回收站、切换主题和重置示例数据。

## 快速开始

### 方式一：直接打开

双击打开 `creator-workspace.html` 即可使用基础功能。

如果浏览器阻止了目录访问或文件系统权限，应用会自动退回到 `localStorage`。这种模式的数据只保存在当前浏览器中，适合临时体验，不适合作为跨设备同步方案。

### 方式二：使用本地静态服务器

建议使用 Chromium 内核浏览器（Chrome 或 Edge）并通过本地服务器访问，以获得更稳定的文件夹访问权限。

```bash
cd "/path/to/AI工作台"
python3 -m http.server 8000
```

然后访问：

```text
http://localhost:8000/creator-workspace.html
```

如果你的环境优先使用项目提供的 Python 运行时，也可以替换为对应的 Python 可执行文件。

### 方式三：启用 Zotero 本机集成

Zotero 集成使用项目内的只读本机桥接服务。它只监听 `127.0.0.1`，不会读取 Zotero 的 SQLite 文件，也不会向 Zotero 写入任何内容。

1. 在 Zotero 中打开 **设置 → 高级**，启用“允许同一台电脑上的其他应用与 Zotero 通信”。
2. 确保 Zotero 正在运行且本机 API 可用。
3. 在项目根目录启动桥接服务：

```bash
"/Users/ffex/.workbuddy/binaries/node/versions/22.22.2/bin/node" zotero-bridge.js
```

4. 在浏览器打开：

```text
http://127.0.0.1:8788/creator-workspace.html
```

5. 进入 **科研 → 文献**，点击“连接 Zotero”。可浏览收藏夹、检索文献，并查看条目摘要、标签和关联笔记。

若 Zotero 未运行或未授权，工作台会显示明确提示；其他工作台功能仍可正常使用。

## 启用 iCloud 数据同步

1. 确保项目目录位于 iCloud Drive 中，并且当前项目下存在 `data/` 文件夹。
2. 使用 Chrome 或 Edge 打开应用。
3. 进入左侧菜单的 **数据管理**。
4. 点击 **连接数据文件夹**，选择当前项目下的 `data/` 文件夹。
5. 应用会在该目录中读写：

```text
data/workspace.json
data/backups/workspace-<时间>.json
```

连接成功后，新增任务、完成打卡、健身记录和其他数据会写入 `workspace.json`。iCloud 负责将该文件同步到其他设备；在其他设备首次使用时，需要在对应浏览器中重新授权同一个 `data/` 文件夹。

### 同步注意事项

- `workspace.json` 是个人运行数据，不是程序源代码，可能包含任务、学习记录和健身记录。
- 多台设备同时编辑同一份数据时，应用会根据版本号检测冲突，并提供加载远端、先导出本地副本后加载远端、保留本地覆盖远端三种处理方式。
- 文件同步依赖浏览器的 File System Access API。若浏览器不支持，应用会显示本地存储状态。
- 应用会定期在 `data/backups/` 中保留最近 5 份文件快照。
- 断开数据文件夹后，应用会回退到当前浏览器的 `localStorage`；断开不会删除 `data/workspace.json`。

## 数据与恢复

应用默认使用以下数据边界：

- **文件同步模式**：`data/workspace.json` 是主数据文件。
- **浏览器本地模式**：数据保存在浏览器 `localStorage` 中，键名为 `creator-workspace-data`。
- **回收站**：删除的数据会先进入应用内回收站，默认保留 30 天；删除后的短时间内可以直接撤销。
- **手动备份**：在数据管理中导出 JSON 文件；重置数据前也会先导出一份备份。

建议在重大调整前先使用 **导出数据**，不要直接手工编辑正在使用的 `workspace.json`。如需迁移数据，可在新设备上使用 **导入数据**，然后再连接目标 `data/` 文件夹。

## Git 管理

项目已经初始化 Git 仓库，默认分支为 `main`。

```bash
git status
git add README.md creator-workspace.html optimization-plan.md .gitignore data/.gitkeep
git commit -m "chore: initialize AI workspace"
```

当前 `.gitignore` 默认忽略：

- `data/` 下的个人运行数据和备份；
- `.workbuddy/`、`.codex/` 等 AI 工具本地状态；
- `.env`、证书、密钥和其他敏感文件；
- 依赖目录、缓存、构建产物、测试报告和覆盖率文件；
- 操作系统元数据、临时文件和本地归档。

其中 `data/.gitkeep` 用于保留空的 `data/` 目录结构。若你明确希望通过 Git 管理 `workspace.json`，需要先评估个人隐私和历史记录风险，再单独调整 `.gitignore`。

## 项目结构

```text
AI工作台/
├── creator-workspace.html   # 应用主体：HTML、CSS 和 JavaScript
├── zotero-bridge.js         # 仅限本机的 Zotero Local API 只读桥接服务
├── data/
│   ├── .gitkeep             # 保留数据目录
│   ├── workspace.json       # 运行时数据，默认不提交
│   └── backups/             # 自动备份，默认不提交
├── optimization-plan.md     # 项目优化规划
├── README.md                # 项目说明
└── .gitignore               # Git 忽略规则
```

## 使用快捷键

- `Cmd/Ctrl + K`：打开全局搜索和命令面板。
- `N`：快速新建任务。
- `1` - `9`：切换常用页面。
- `?`：打开快捷键帮助。
- 在任务文字上双击：编辑任务。
- 聚焦任务复选框后按 `Space` 或 `Enter`：切换完成状态。

## 数据计算规则

- 任务完成比例根据任务的完成状态自动计算，不支持手动修改任务完成比例。
- 首页总完成率会汇总工作台首页、每日计划、AI 学习、英语学习、AI 漫剧和科研任务。
- 每日打卡连续天数根据当天达到打卡阈值的历史记录计算。
- 健身统计根据训练日志计算本周训练次数、总时长、卡路里和连续训练天数。
- 内容复盘中的互动转化率属于业务指标，可手动维护，不等同于任务完成比例。

## 已知边界

- 默认工作台仍是单文件前端应用；仅在启用 Zotero 时使用项目内的 `zotero-bridge.js` 本机只读服务。
- iCloud 只负责文件同步，不提供实时协同编辑；请避免多台设备同时写入。
- 浏览器的目录授权与权限状态由浏览器管理，切换设备或浏览器后通常需要重新授权。
- 新闻热点等部分内容目前是预置数据，不代表自动联网更新。
- 项目数据模型由页面内 JavaScript 维护，扩展功能时需要同步考虑默认数据、迁移逻辑、导入导出和旧数据兼容。

## 后续开发建议

1. 将内联 JavaScript 和 CSS 拆分为模块，并增加自动化语法检查。
2. 为数据模型增加显式版本迁移机制，降低长期迭代中的兼容风险。
3. 为跨设备同步增加更细粒度的合并策略和写入锁，减少并发编辑冲突。
4. 增加浏览器端测试，覆盖数据导入、冲突处理、回收站恢复和健身日志等关键流程。
